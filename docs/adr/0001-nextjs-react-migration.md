# ADR 0001: Next.js / Reactへ段階的に移行する

- Status: Accepted
- Date: 2026-10-02
- Scope: フロントエンドの実装方式と初期デプロイ方式

## Context

現在のサイトは、`src/index.html`、`src/style.css`、`src/script.js`で構成されている。プロフィール、スキル、プロジェクト、活動実績がHTMLに直書きされ、スクロール演出やプロジェクト画像の切り替えがDOM操作として実装されている。

今後は、プロジェクト詳細ページ、コンテンツの再利用、型安全なデータ管理、将来的な管理画面を追加しやすい構造にしたい。一方で、既存のデザインとCloudflareで取得したドメインは維持したい。

## Decision

1. フロントエンドをNext.jsのApp Router、React、TypeScriptへ段階的に移行する。
2. 初期移行では既存のCSSと画像をできるだけ再利用する。Tailwind CSSへの全面移行はReact化と分離する。
3. 静的な公開ページを優先し、初期の公開先は既存のCloudflare Workerを継続する。Next.jsの出力・実行方式はReact移行時にWorker上で検証する。
4. HTMLのセクションをReactコンポーネントへ分割し、コンテンツは表示コンポーネントから分離する。
5. DOMイベント中心の処理は、必要な箇所だけClient Componentへ移し、純粋な表示はServer Componentまたは静的生成を優先する。
6. DB・管理画面はReact化と同時には導入せず、必要性を確認した後の別段階とする。

## Alternatives considered

### 現在のHTML / CSS / JavaScriptを継続する

運用は最も単純だが、ページ増加、データ再利用、詳細ページ、管理機能を実装するたびに保守コストが上がるため採用しない。

### Vite + Reactへ移行する

Reactの学習・部品化には適している。しかし、将来的にサーバー側のデータ取得、メタデータ、詳細ページ、管理画面を同一アプリで扱う可能性があるため、ルーティングとサーバー機能を持つNext.jsを採用する。

### 最初からDB・管理画面まで作る

更新の仕組みは得られるが、デザイン移行、データ設計、認証、画像管理、公開方式を同時に扱うことになる。初期の不確実性が高いため、最初の移行範囲には含めない。

## Consequences

### Positive

- Reactコンポーネントを再利用できる。
- `/projects/[slug]`のような詳細ページを追加しやすい。
- コンテンツと表示ロジックの境界を先に作れる。
- 将来DBへ移行しても、表示コンポーネントの変更を小さくできる。

### Negative

- Node.js、パッケージ管理、ビルドが必要になる。
- Cloudflare Workers上で使うNext.js機能と、その実行方式の互換性を管理する必要がある。
- 既存のCSSを再利用するため、初期段階ではCSS設計の改善が別課題として残る。

## Exit criteria

- 既存の主要セクションがReactコンポーネントとして表示される。
- 主要な見た目、外部リンク、画像・動画表示、レスポンシブ表示が維持される。
- React化後のビルドとCloudflare Workerのプレビュー確認が成功する。
- 既存HTMLを直接編集しなくても、データ定義を変更してプロジェクトを増やせる。
